# NiceTunnel (نایس تانل)

ساخته‌شده توسط **Arsham Smoke** (آرشام اسموک) · لایسنس MIT

دو نوع تانل بین دو سرور (مثلاً ایران و خارج) با منوی تعاملی. روی هر دو سرور با یک دستور نصب می‌شود.

| نوع | برای چه | چه چیزی عبور می‌کند |
|---|---|---|
| **TCP tunnel** | تانل معکوس معمولی | هر ترافیک TCP (VLESS، Trojan، SSH و مانند آن) |
| **Spoof tunnel** | وقتی تانل‌های معمولی بسته شده‌اند | فقط UDP (مثلاً WireGuard) |

```
کاربر ──► سرور ایران ◄══ تونل ══ سرور خارج ──► سرویس روی سرور خارج
```

- سرور خارج خودش به سرور ایران وصل می‌شود، پس در تانل TCP فقط سرور ایران به پورت ورودی باز نیاز دارد.
- احراز هویت با توکن مشترک (HMAC)، اتصال مجدد خودکار، اجرا به صورت سرویس systemd (بعد از ریبوت خودش بالا می‌آید).
- چند تونل مستقل با slot از ۱ تا ۱۰ (از هر دو نوع)، فوروارد چند پورت، و بهینه‌سازی BBR از داخل منو.
- منوی رنگی با بنر گرادیانی، مراحل ساخت تونل با شماره قدم و تیک سبز، انتخاب با کلیدهای جهت‌نما، و چند تم رنگی.
- تونل‌ها ترافیک را **رمز نمی‌کنند**. روی آن‌ها پروتکل‌هایی را عبور بدهید که خودشان رمزنگاری دارند (TLS، VLESS، Trojan، SSH، WireGuard و مانند آن).

## ۲. نصب روی هر دو سرور

با `ssh root@IP` وارد سرور شوید (مستقیم با root، چون `sudo` با این دستور کار نمی‌کند؛ اگر یوزر root نیستید اول `sudo -i` بزنید)، بعد:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/یوزرنیم_شما/nicetunnel/main/install.sh)
```

نصب انجام می‌شود و منو باز می‌شود. بعداً هر وقت خواستید منو را باز کنید:

```bash
nicetunnel
```

## ۳. ساخت تانل TCP از داخل منو

داخل منو با کلیدهای **↑ و ↓** بین گزینه‌ها بروید و **Enter** بزنید. کلید عدد (مثلاً `1`) هم مستقیم همان گزینه را انتخاب می‌کند. **Esc** یک قدم برمی‌گردد و در جاهایی که باید تایپ کنید، نوشتن `<` و Enter یک مرحله به عقب می‌رود. جواب‌های داده‌شده با تیک سبز بالای صفحه می‌مانند.

۱. روی **سرور ایران**: `Create tunnel` ← `TCP tunnel` ← `Iran server` ← slot (Enter برای پیش‌فرض) ← bridge port (پیش‌فرض 7000) ← پورت‌های عمومی (مثلاً `443`) ← توکن (Enter تا همان توکن پیشنهادی را قبول کند) ← در صفحه Review روی `Create tunnel` بزنید. توکن را کپی کنید.

۲. روی **سرور خارج**: `Create tunnel` ← `TCP tunnel` ← `Foreign server` ← همان slot و همان bridge port ← آی‌پی سرور ایران ← همان توکن ← Enter ← `Create tunnel`.

۳. در منو وضعیت هر دو باید `active` باشد. `Manage tunnels` ← تونل ← `Logs` برای دیدن لاگ.

مثال پورت‌ها: `443` یعنی کاربر به 443 ایران وصل شود و به 443 سرور خارج برسد. `8443:8080` یعنی به 8443 ایران وصل شود و به 8080 سرور خارج برسد.

پورت bridge و پورت‌های عمومی باید در فایروال سرور ایران (و پنل فایروال دیتاسنتر، اگر دارد) باز باشند. اگر `ufw` روشن باشد، منو خودش پیشنهاد باز کردنشان را می‌دهد.

## ۴. تانل اسپوف (Spoof tunnel)

### این تانل چیست؟

در تانل اسپوف، هر دو سرور بسته‌هایشان را با **آی‌پی مبدأ دیگری** می‌فرستند (آی‌پی‌ای که شبکه در بین راه اجازه‌ی عبورش را می‌دهد). رفت و برگشت از آی‌پی‌های جدا می‌آید، پس شبیه یک اتصال معمولی بین دو سرور دیده نمی‌شود. نوع بسته را می‌شود `udp`، `tcp` (بسته‌ی SYN) یا `icmp` (شبیه پینگ) انتخاب کرد.

```
برنامه (WireGuard) ──UDP──► سرور ایران ══ بسته‌های با آی‌پی مبدأ دیگر ══► سرور خارج ──UDP──► WireGuard
```

### قبل از شروع، این چهار واقعیت را بدانید

۱. **هاستینگ باید اجازه‌ی جعل آی‌پی بدهد.** خیلی از دیتاسنترها بسته‌ای را که آی‌پی مبدأ آن مال خودشان نیست همان اول دور می‌ریزند. در این حالت تانل اسپوف کار نمی‌کند و کاری از منو برنمی‌آید. با «تستر اسپوف» (پایین) این را قبل از هر کار دیگری بفهمید.

۲. **فقط UDP.** تانل اسپوف یک لوله‌ی UDP است. برای WireGuard عالی است، اما پروکسی‌های TCP (مثل VLESS) مستقیم رویش نمی‌روند؛ باید WireGuard را روی آن بگذارید.

۳. **آی‌پی‌های مجاز را باید خودتان پیدا کنید.** اینکه کدام آی‌پی‌های مبدأ از شبکه‌ی شما عبور می‌کنند به شبکه‌ی همان لحظه بستگی دارد. تستر داخل منو دقیقاً برای همین است.

۴. **تانل رمز نمی‌کند.** هر بسته امضا (HMAC) می‌شود و بسته‌ی تکراری یا بسته‌ای که از طرف دیگران ساخته شده رد می‌شود، اما محتوا رمز نمی‌شود. رمزنگاری را WireGuard انجام می‌دهد.

این برنامه فقط با آی‌پی سرور مقابلِ خودتان حرف می‌زند، و فقط بین دو سرور خودتان استفاده کنید.

### مرحله‌ی ۱: تست (روی هر دو سرور)

از منوی اصلی `Spoof tester`:

۱. `Check this server`: نشان می‌دهد سرور اصلاً می‌تواند بسته‌ی خام بسازد یا نه (بعضی VPSها مثل OpenVZ/LXC نمی‌گذارند).

۲. روی سرور A گزینه‌ی `Receive` را بزنید (نوع بسته، پورت و مدت انتظار را انتخاب کنید). سرور منتظر می‌ماند.

۳. تا وقتی منتظر است، روی سرور B گزینه‌ی `Send` را بزنید: آی‌پی واقعی سرور A، همان نوع بسته و پورت، و آی‌پی‌هایی که می‌خواهید امتحان کنید (مثلاً `10.0.0.0/28` یا `5.5.5.1-5.5.5.9` یا `1.2.3.4`).

۴. در پایانِ `Receive`، لیست آی‌پی‌هایی که رسیدند چاپ می‌شود. **این لیست همان «Source IPs» تانل سرور B است.** اگر لیست طولانی باشد در فایلی روی سرور A ذخیره می‌شود (مسیرش چاپ می‌شود).

۵. برای جهت دیگر، نقش‌ها را عوض کنید (Receive روی B و Send روی A). لیستی که روی B چاپ می‌شود، «Source IPs» تانل سرور A است.

اگر `Receive` نوشت بسته‌های عادی رسیدند ولی هیچ بسته‌ی جعلی نرسید، یعنی شبکه جعل را می‌بندد و تانل اسپوف روی این مسیر کار نمی‌کند.

### مرحله‌ی ۲: ساخت تانل

روی **سرور ایران**: `Create tunnel` ← `Spoof tunnel` ← `Iran server` ← slot ← آی‌پی واقعی سرور خارج ← نوع بسته ← پورت تانل (برای icmp پورت لازم نیست) ← Source IPs (لیست تستر) ← پورت UDP برنامه‌ها (مثلاً 51820، همانی که در WireGuard کاربران به‌عنوان Endpoint می‌گذارید) ← توکن ← `Create tunnel`.

روی **سرور خارج**: `Create tunnel` ← `Spoof tunnel` ← `Foreign server` ← slot ← آی‌پی واقعی سرور ایران ← **همان نوع بسته و همان پورت تانل** ← Source IPs ← آدرس سرویس UDP همین سرور (مثلاً `127.0.0.1:51820` برای WireGuard) ← **همان توکن** ← `Create tunnel`.

بعد از چند ثانیه `Manage tunnels` ← تونل ← `Logs`. در سرور ایران باید پیام `the other server answered: the spoof tunnel is working` را ببینید.

### مرحله‌ی ۳: WireGuard روی تانل

- روی سرور خارج WireGuard سرور را روی پورت 51820 بالا بیاورید.
- در کلاینت‌ها `Endpoint = IP_سرور_ایران:51820` بگذارید و **MTU = 1280** (تانل دیتاگرام بزرگ‌تر از 1400 بایت را رد می‌کند و در لاگ هشدار می‌دهد).

### نکته‌ها

- روی سرور خارج با نوع `icmp`، تا وقتی تانل روشن است سرور به پینگ جواب نمی‌دهد (بعد از توقف تانل برمی‌گردد).
- تانل اسپوف باید با root اجرا شود (منو و سرویس systemd همین کار را می‌کنند).
- پنل فایروال دیتاسنتر، اگر دارد، باید ورودی نوع بسته و پورت تانل را باز بگذارد.

## ظاهر منو و تم‌ها

از منوی اصلی گزینه `Theme` را بزنید و یکی از چهار تم را انتخاب کنید: `ocean` (فیروزه‌ای تا بنفش)، `sunset` (زرد تا صورتی)، `matrix` (سبز) یا `mono` (سفید و خاکستری). انتخاب شما ذخیره می‌شود.

اگر ترمینال شما چیزی را درست نشان نداد، منو را با یکی از این‌ها باز کنید:

```bash
NICETUNNEL_ASCII=1 nicetunnel     # به جای مربع و پیکان، کاراکترهای ساده
NICETUNNEL_SIMPLE=1 nicetunnel    # لیست شماره‌دار به جای انتخاب با جهت‌نما
NO_COLOR=1 nicetunnel             # بدون رنگ
```

بنر بالای منو (اسم، نسخه و نام سازنده) در تابع `banner` و `header` داخل `nicetunnel.sh` است و با VS Code راحت تغییر می‌کند.

## اجرای دستی بدون منو (برای تست)

```bash
export NICETUNNEL_TOKEN=یک_رشته_حداقل_۱۶_کاراکتری

# تانل TCP
python3 nicetunnel.py server --bridge 7000 --ports 443       # سرور ایران
python3 nicetunnel.py client --server IP_IRAN --bridge 7000  # سرور خارج

# تانل اسپوف (با root)
python3 nicetunnel.py spoof-entry --peer IP_KHAREJ --spoof-ip 10.0.0.0/28 --port 4500 --listen-port 51820   # سرور ایران
python3 nicetunnel.py spoof-exit  --peer IP_IRAN  --spoof-ip 10.0.1.0/28 --port 4500 --forward 127.0.0.1:51820  # سرور خارج

# تستر
python3 nicetunnel.py spoof-test recv --port 4500 --seconds 60                        # سرور دریافت‌کننده
python3 nicetunnel.py spoof-test send --peer IP_RECEIVER --port 4500 --spoof-ip 10.0.0.0/28   # سرور فرستنده
```
